# Issues Log

Append solved bugs and problems here. Entries are append-only and use ISO dates.

## 2026-06-11 [ArchitectureBoundary] in profiles/application/port

**Symptom:** The stricter project architecture required ports under `domain/port`, while earlier profile work had ports outside the final target structure.
**Root cause:** An earlier hexagonal variant placed ports in the application side instead of using the repository standard defined for this project.
**Fix:** Move input ports, command/result records, and output ports to `profiles/domain/port/in` and `profiles/domain/port/out`, then update controllers, use cases, and adapters to import the domain ports.
**Prevention:** For this repository, always create input ports under `domain/port/in` and output ports under `domain/port/out`.

## 2026-06-11 [ArchUnitCompatibility] in build.gradle

**Symptom:** The architecture test could not reliably enforce boundaries with the Java 26 toolchain when ArchUnit did not support the generated bytecode level.
**Root cause:** The initial ArchUnit dependency version was too old for Java 26 class files.
**Fix:** Use `com.tngtech.archunit:archunit-junit5:1.4.2`.
**Prevention:** Before locking architecture-test dependencies, verify the dependency supports the configured Java toolchain.

## 2026-06-11 [DomainInvariant] in cutting/domain/model/CuttingQuantities.java

**Symptom:** The critical cutting rule could otherwise be enforced only by the database constraint after persistence.
**Root cause:** The domain model needed an explicit value object for cutting quantities.
**Fix:** Add `CuttingQuantities` and validate `initialQuantity > 0`, non-negative good and scrap quantities, and `initialQuantity == goodQuantity + scrapQuantity`.
**Prevention:** Put manufacturing invariants in domain models or value objects before saving to persistence.
